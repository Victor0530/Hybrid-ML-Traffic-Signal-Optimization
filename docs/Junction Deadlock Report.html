The RL environment deadlocks the junction RL 环境会让路口死锁

From提交人 Evan Chong (Lane A) To致 project owner (Lane D)项目负责人（Lane D） Affects影响 all RL agents所有 RL agent 2026-11-19

When an agent switches between the through phases (0 ↔ 4), TrafficEnvironment inserts only the yellow phase and goes straight to the other through phase. It skips the protected-left clearance (phases 2 and 6) that the native fixed-time program always runs. Permissive left-turners already inside the junction get trapped by the crossing flow, and the junction deadlocks until SUMO teleports them after the default 300 s.

agent 在两个直行相位之间切换（0 ↔ 4）时，TrafficEnvironment 只插入黄灯，然后直接进入另一个直行相位，跳过了固定配时方案每次都会执行的左转专用清空相位（2 和 6）。已经开进路口的让行左转车会被横向车流困住，路口随之死锁，直到 SUMO 按默认的 300 秒把这些车瞬移走。

Why agents cannot fix this themselves为什么 agent 自己解决不了

  • Choosing phase 2 or 6 holds it for at least one 15 s decision interval, compared with 6 s in the fixed plan. Cycling through all four phases this way overloads the junction (mean queue 136 on medium).
  • The observation has no left-lane or junction-internal information, so an agent cannot see a deadlock building up.
  • This affects Lane D's DQN and Double DQN as well as Lane A's Q-Learning.
  • 选择相位 2 或 6 后，至少要保持一个 15 秒的决策间隔，而固定配时只用 6 秒。如果用这种方式依次走完四个相位，路口会超负荷（medium 场景平均排队 136）。
  • observation 里没有左转车道或路口内部的信息，agent 看不到死锁正在形成。
  • 这个问题会影响 Lane D 的 DQN 和 Double DQN，也会影响 Lane A 的 Q-Learning。

Possible fixes可能的修复方式

Each option changes frozen files, so it needs a contract v2 decision.

每种方式都要修改冻结的合约文件，需要作为 contract v2 来决定。

Run the left clearance automatically自动执行左转清空

When leaving a through phase, run a short protected-left phase before the next green (0 → 1 → 2 for a few seconds → 3 → 4), as the native plan does.

离开直行相位时，在进入下一个绿灯前先跑一个短的左转专用相位（0 → 1 → 2 持续几秒 → 3 → 4），和原生方案一致。

在 observation 里加入左转车道排队，并且/或者缩短 decision_interval，让 agent 能学会什么时候使用相位 2 和 6。

Smaller contract issues其他较小的合约问题

  • contract_v1.md §3.2 lists actions as 0–3, but env.step() accepts only phase numbers 0, 2, 4, 6; passing 1 or 3 raises ValueError. The doc and the code should agree.
  • TrafficEnvironment.reset() rewrites sumo/routes/generated/<scenario>.rou.xml on every call. Two processes running the same scenario in parallel corrupt that file (invalid document structure, then Connection closed by SUMO).
  • Registering an agent in agents.py, as the contract instructs, breaks test_registry_starts_empty…. On lane-a the assertion is relaxed to "dummy" not in available_agents().
  • contract_v1.md §3.2 把动作写成 0–3，但 env.step() 只接受相位编号 0、2、4、6，传入 1 或 3 会抛出 ValueError。文档和代码需要统一。
  • TrafficEnvironment.reset() 每次调用都会重写 sumo/routes/generated/<scenario>.rou.xml。两个进程并行跑同一个场景会把这个文件写坏（报 invalid document structure，接着是 Connection closed by SUMO）。
  • 按合约要求在 agents.py 里注册 agent，会让 test_registry_starts_empty… 失败。lane-a 分支上已把这条断言放宽为 "dummy" not in available_agents()。
